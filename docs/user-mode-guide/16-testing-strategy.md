# 16 · Testing strategy

Status: T01–T40 and A01–A10 remain **proposed** release gates for the whole product; none has been executed as a release gate. T41–T48 and A11–A13, added 2026-09-14, cover the Guide Engine v2 work in [20](20-guide-engine-migration-plan.md) that **is implemented and runs in CI** — backend pytest, web vitest and Playwright against installed Chrome — with counts and remaining limits recorded in [19](19-implementation-status.md). Nothing here claims the native client, the hardware matrix or live provider evaluation has been tested; no request in CI reaches a provider. Use synthetic/redacted fixtures and isolated Supabase/PostgreSQL/storage environments; never real customer screenshots in CI.

| T39 | Usability | Pilot tests instruction clarity, cannot-find recovery, privacy comprehension, task completion; no unreadable idle fade or hidden stop |
| T40 | Full Windows release flow | Signed fresh install → login → Python/VS Code/manual+live+voice → pause/revoke/network/restart → complete → delete → uninstall; evidence report per OS/app build |
| T55 | Provider breadth | Every service serves the engine roles through one adapter; the image and the declared schema reach each one; a local service refuses a non-loopback host and sends no credential; a remote service refuses plain HTTP; refusals, truncation and nonsense are each reported as themselves and never as a verdict; the source gate still forbids provider names outside `app/providers/` |
| T53 | Marks and overlay | Inverted, collapsed, non-numeric and out-of-frame geometry dropped or clamped; common words never carry a match; the shorter label wins a tie; no confident match means no mark; a restricted control is never pointed at; normalised coordinates survive resize and letterboxing; a label never covers what it names |
| T54 | Idle staging | Each stage fires once and in order; activity restarts the quiet period; the stop stage does not repeat; the copy claims only what a browser can observe, and both losing stages promise the place is kept |
| T52 | Adaptive guidance | Every stage maps to one decision; a wrong application outranks a satisfied step; only a redirect or a dialog costs a new instruction; a forward skip is offered only above the acting floor, names every step it would settle, and settles nothing without the ids echoed back; a step behind the guide and a guard-blocked step are both refused; repeated off-track contexts raise the existing stuck signal |
| T51 | Screen context | The digest is stable across re-wording, confidence and nudged geometry, and changes for anything a guide would act on; a control whose label addresses the model or names a restricted action is dropped; a satisfied stage below the acting floor is downgraded; a tick records a belief, spends the shared budget and verifies nothing; the observer is told the step and later titles and no goal or history |
| T60 | Evidence verification | A shared screenshot earns `verified` only at 0.85 and above with the criterion satisfied; the middle band records `inconclusive` and advances nothing; a screenshot showing the step undone records `mismatch`, counts an attempt and leaves the step current; evidence from another task, more than one image, and a deleted image are each refused; the self-report arm is unchanged |
| T59 | Erasure | A deleted session removes every row and byte under it and leaves its task; a deleted task removes its sessions and images; a deleted account removes every owned row and revokes every token issued before the request; the confirmation phrase is required exactly; a second deletion produces no second receipt; another owner is untouched; and a table added to the schema without being erased fails the suite |
| T49 | Guidance surfaces and fallbacks | All three surfaces offered whatever the browser supports, each unavailable one carrying its reason; the page is preselected so Start opens no OS window and no picker unasked; a refused Picture-in-Picture window falls back to the page with a message and a running guide; closing the floating window returns the guide to the page and does not end the session; a local mirror declares that it is not observation and never becomes the frame source |
| T41 | Tiered observation admission | T0 motion gate and T1 admission against synthetic frame sequences; a static screen admits 0 frames per minute and one scripted UI change admits exactly 1; tiers 0 and 1 open no socket |
| T42 | Observation route, budgets and bands | Per-session semaphore keeps one frame in flight; per-session and per-owner budgets cap calls; a verdict advances only above the confidence threshold and `ask`/`wait` advance nothing; budget exhaustion stops sending and leaves the guide working on manual checking |
| T43 | Continuous-observation consent and stop | Nothing is sent before the [21](21-observation-consent-notice.md) notice is accepted at its recorded version and a single window chosen; masked regions are painted out before encoding; the counter shown is the server's `frames_observed`; one tap stops and increments `control_epoch`, and a late verdict cannot apply |
| T44 | Server-driven guide and self-report | The island renders the engine's published instruction, not plan text; a self-report records `user_reported` with `evidence_available=false` and no `verified_at`; evidence sent to the self-report arm is refused with `evidence_required` rather than downgraded; an exhausted plan retires its current instruction |
| T45 | Stuck detection and replan | Observer anomaly, a twice-claimed step and a step current beyond the timeout each record `session.stuck_detected` once and act on nothing; replan copies every settled step with its status, `verified_at` and `previous_step_id`, proposes only the remainder, and produces a draft that must be confirmed |
| T46 | Provider role abstraction | Identical fixtures through every adapter serving a role satisfy the same schema and the same guard; refusal and truncation are reported as themselves and never as a verdict; source of `app/` outside `app/providers/` names no provider, adapter module or model |
| T47 | Conversation import | An instruction hidden in a transcript becomes neither goal nor step; a restricted action is kept and marked `block` rather than dropped; recognized secrets are redacted before the transcript row is written and the count is shown; provenance appears on the draft; an import confirms nothing and starts nothing |
| T48 | Completion honesty and summary record | `achieved` is refused with `verification_required` unless every required step is verified; `user_reported` requires every required step settled and none blocked; the summary separates verified from unverified steps and names skipped, blocked and never-started ones; stopping writes a summary too |

Unit tests: policy dispositions, state reducers, schema validators, coordinate transforms, retention cutoff and budgets. Integration: real PostgreSQL transactions/constraints, private object store abstraction, Supabase validation fixture/mock JWKS plus isolated live Auth test. Contract: generated OpenAPI/JSON schemas and captured sanitized examples. End-to-end: web browser flow and native UI Automation/manual QA; provider nondeterminism evaluated separately with labeled fixtures. Do not use SQLite to claim PostgreSQL transaction/security behavior is validated.

These scenarios must run against production-like contracts and the real native capture boundary, not just mocked UI buttons. A03/A04 require instrumented capture/upload timestamps and network sink records with synthetic images; a screenshot showing a paused label alone is insufficient proof that capture stopped.

## Fixture and hardware matrix

At least: Windows 11 x64 release build selected under D03, Windows 10 22H2 x64 on approved servicing path before any compatibility claim; 1/2/3 monitors, left/top negative coordinates, mixed DPI, portrait, docking/unplug, locked desktop, sleep/resume, minimized/occluded/straddled target, UAC, protected content and shortcut conflicts. Use 1080p and 4K plus small work-area/text-zoom stress. Enumerate exact OS/app/client/provider versions in report, not just “Windows passed.” ARM64/RDP are unsupported until separate tests.

Provider evaluation corpus: ≥100 redacted synthetic tasks with held-out failures/ambiguous UI; ≥200 labeled verification decisions to estimate false-pass target without treating model confidence as accuracy. Report confidence intervals/sample size and domain breakdown; pilot thresholds in 01 are hypotheses. Repeat provider evaluation after model/prompt/app version changes. No provider request in ordinary unit CI; the opt-in integration job is `.github/workflows/provider-smoke.yml`, which runs `scripts/smoke_provider.py` by manual dispatch only, against a key held in a protected environment, and keeps the answers as an artifact. It sends one synthetic request per role and prints what came back, including a refusal or a guard rejection; it is an instrument, not a gate, and asserts nothing about confidence.

## Release evidence and decisions

Evidence artifact: test ID, contract/commit version, OS/app/provider versions, fixture IDs, expected/actual state, sanitized trace IDs, pass/fail, reviewer and unresolved issues. Privacy logs contain no raw media. Safety-critical T06/T11/T12/T15/T16/T17/T20/T29/T32–T37 and T43 must all pass; no launch with known unauthorized capture, cross-owner disclosure or false deletion. D01–D07 unresolved gates require explicit resolution before corresponding release, not blanket coding blockage. Traceability: [17](17-traceability-matrix.md). SEC-01–SEC-16 covered by tests above.
